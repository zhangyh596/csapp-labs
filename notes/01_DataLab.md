## 3. 整数部分的核心方法

### 3.1 逻辑等价变换

`bitXor` 使用德摩根律和与非结构构造异或；`negate` 使用补码取负的恒等式 `~x + 1`。这类题目的关键不是“模拟”目标运算，而是把目标逻辑拆成题目允许的基本运算。

### 3.2 特殊值排除

`isTmax` 利用 `Tmax + 1 == Tmin` 以及取反关系识别最大补码整数，并额外排除 `-1` 这个伪匹配值。这里体现了边界值推理的重要性：只验证主等式不足以覆盖补码溢出产生的特殊情况。

### 3.3 掩码构造

`allOddBits` 通过若干个不超过 `0xFF` 的常量拼接出奇数位掩码，再比较目标位是否全部为 1。Data Lab 经常限制大常量，因此应熟悉左移、或运算与局部模式重复构造全字掩码的方式。

### 3.4 符号位与溢出

`isAsciiDigit` 和 `isLessOrEqual` 都需要避免直接减法可能造成的有符号溢出：

- ASCII 判断先利用高位范围缩小候选区间，再观察差值的符号位。
- 大小比较先区分 `x`、`y` 符号是否不同。符号不同的时候不能盲目相减；符号相同的时候，差值才可以安全地反映大小关系。

### 3.5 用全 0 / 全 1 掩码实现分支

`conditional` 将 `!!x` 扩展为全字掩码，然后用按位与和或实现选择 `y` 或 `z`。这对应硬件层面的无分支选择：掩码为全 1 时保留一侧，为全 0 时保留另一侧。

### 3.6 无 `!` 实现逻辑非

`logicalNeg` 利用 `x` 与 `-x` 的符号位特征识别零值，并单独覆盖 `Tmin`。补码中 `Tmin` 的相反数仍然是自身，是这道题最容易遗漏的边界。

### 3.7 二分查找最高有效位

`howManyBits` 先将负数转换到便于统一处理的形式，再按 16、8、4、2、1 位逐级缩小搜索范围，计算最高有效位位置。它体现了“位级二分搜索”思想：每次根据高半区是否存在 1，决定是否跳过对应位数。

## 4. 浮点部分的核心方法

这些题目处理的是 IEEE 754 单精度数的 **位表示**，不是 C 语言浮点运算。代码将字段拆成：

- 符号位 `sign`：最高位；
- 指数 `exp`：接下来的 8 位；
- 尾数 `frac`：最低 23 位。

### 4.1 `floatScale2`

按指数分为三类：

- `exp == 0xFF`：NaN 或无穷，按题意原样返回；
- `exp == 0`：非规格化数，主要通过尾数左移实现乘 2；
- `0 < exp < 0xFF`：规格化数，指数加一；达到 `0xFF` 时转为无穷表示。

这里的重点是理解非规格化数向规格化数过渡时的进位，以及 NaN 保持原比特模式的要求。

### 4.2 `floatFloat2Int`

代码先解析符号、指数和尾数，计算真实指数 `E = exp - 127`，再补上规格化数隐藏的最高位。根据 `E` 判断：

- 绝对值小于 1 时结果为 0；
- 超出整数可表示范围、NaN 或无穷时返回题目指定的 `0x80000000u`；
- 其余情况根据 `E` 与 23 的关系进行左移或右移，再按符号取值。

此题的关键是区分“浮点编码的指数”与“实际二进制指数”，并正确处理隐藏位和范围边界。

### 4.3 `floatPower2`

`floatPower2` 根据 `x + 127` 判断结果属于：

- 规格化数：构造指数域；
- 溢出：返回正无穷；
- 可表示的非规格化数：设置尾数中的对应位；
- 过小：返回 0。

这道题集中考查指数偏置、规格化/非规格化边界和下溢行为。

## 5. 实验的调试与工程习惯

1. **小步提交**：每个函数单独提交，提交粒度清晰。
2. **先理解边界，再写表达式**：代码注释大量记录了补码、符号位、掩码和 IEEE 754 边界推理。
3. **整数题与浮点题分阶段处理**：先完成位运算基础，再进入浮点编码解析，难度逐步上升。
4. **把验证约束纳入实现过程**：`bits.c` 保留了题目对 `dlc`、操作数数量和允许类型的说明，说明实现时需要同时满足语义正确性与编码规则。

## 6. 可能的典型风险点

以下是从最终代码能够反推出的高风险位置，不代表当时一定出现过对应错误：

- `isTmax` 若不排除 `-1`，会产生假阳性。
- `isLessOrEqual` 若对不同符号的数直接相减，可能因为溢出得出错误结果。
- `logicalNeg` 若只检查 `x` 与 `-x` 的符号，可能遗漏 `Tmin`。
- `howManyBits` 若忘记负数需要按位取反逻辑处理，或者忘记符号位，边界值会出错。
- `floatScale2` 需要分别处理 NaN、无穷、规格化数和非规格化数。
- `floatFloat2Int` 需要在移位前判断指数范围，避免非法移位或超出整数范围。
- `floatPower2` 需要准确计算非规格化数的最低可表示指数，不能只处理规格化数和无穷。

## 7. 建议的复现验证流程

如果以后需要重新确认实验结果，可以在 `DataLab` 目录执行：

```bash
make clean
make btest
./dlc bits.c
./dlc -e bits.c
./btest
./btest -g
```

针对单个函数可以缩小范围，例如：

```bash
./btest -f howManyBits
./btest -f floatScale2
./btest -f floatFloat2Int
./btest -f floatPower2
```

观察位级表示时可以使用：

```bash
./ishow 0x80000000
./fshow 0x7f800000
```

若出现失败，不要只看最终返回值；应优先记录输入的十六进制形式、函数输出、期望输出，以及相关符号位/指数域/尾数字段。

## 8. AI Infra 映射

- **掩码与无分支选择**：`conditional` 的全字掩码选择对应 SIMD/CUDA 中常见的 predicate mask 和 branchless select，可减少分支发散。
- **位域解析**：浮点题拆分 sign/exp/frac 的方式对应 CUDA kernel、量化推理和张量格式转换中的 bit-level packing/unpacking。
- **边界值优先**：`Tmin`、零、NaN、无穷和非规格化数的处理，类似推理系统中对异常输入、溢出和下溢的防御式处理。
- **分层搜索**：`howManyBits` 的二分式位搜索与高性能系统中的层级索引、前导零计数和快速范围定位具有相同的结构思想。
- **小步提交与可验证性**：每题独立提交的方式对应 AI Infra 工程中可回滚、可定位的增量改动，尤其适合底层内存和 kernel 优化。

## 9. 总结

这次 Data Lab 的主线是：在严格的语法和操作数约束下，把整数补码规则、符号位逻辑、掩码构造以及 IEEE 754 编码规则转化为可验证的位级表达式。
